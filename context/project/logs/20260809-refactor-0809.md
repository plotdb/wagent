## 改用真正的 @plotdb/block（HTML-based）

原自製的 js block 格式改為真正的 `@plotdb/block`：

 - block 檔改為 HTML（root `<div>` + 自動 scope 的 `<style>` + `<script type="@plotdb/block">`），workspace block 路徑改為 `blocks/<name>/index.html`
 - 安裝 `@plotdb/block` 及相依（proxise、semver、csscope、rescope），以 fedep 複製 dist 到 `web/static/assets/lib/`（`frontendDependencies.modules` 只收前端 lib）
 - 自製 loader 移除；入口頁改用 `block.manager` + registry（app block 對應 `/refactor-0809/block/`、lib 對應 `/assets/lib/`）
 - chat / sandbox 的 base-derived 兩層改用 `pkg.extend`（`dom: 'overwrite'`）+ `opt.parent.interface()`；base 為 headless block
 - sandbox 渲染 workspace block 時每次建新 manager 避免 cache 到舊版
 - prompt 改教 HTML block 格式；既有三個 workspace block 轉為 index.html（index.js 保留給舊頁面）
 - 踩坑：csscope 的一般 selector 只套到 root 的子孫；要樣式 root 自身用 `:scope { ... }`（csscope 會換成對應 scope selector），chat / sandbox 視覺層均以此實作（prompt 與 guide 均已註明）
 - 端到端驗證（openai / gpt-5）：生成新 block（每月營收折線圖）直接輸出正確 HTML 格式，chat 自動切換 + sandbox 渲染正常
 - 順手修正 guides 的 `@plotdb/block` 說明：補 HTML 檔案格式、interface/destroy、scope 限制；修正 `parent` 為 factory 物件（非 interface）


## 模組化為 @plotdb/agent

refactor-0809 的成果抽成獨立模組,以 npm workspace 掛回 host:

 - `packages/agent/`(`@plotdb/agent`):`api/`(router factory + wsenv + llm + prompt + providers)與 `block/`(chat / sandbox 各含 base 層);root `package.json` 加 `workspaces: ["packages/*"]`
 - 模組入口即 `api/index.js`;前端 block 由 router 自己以 `/block/*` 提供,host 不需知道模組實體路徑
 - host 掛載:`app.use('/api/agent', require('@plotdb/agent')({workspace: 'workspace', log}))`;入口頁 `web/src/pug/agent/index.pug`(組合層,載 lib + 建 manager + 接線)
 - log 預設 noop,由 host 注入;providers 收進模組的 `api/providers/`
 - 前端 block 改由 fedep 供應:`frontendDependencies` 加入 `{name: '@plotdb/agent', dir: 'block'}`,pin 到 `assets/lib/@plotdb/agent/<version>/`(`main` symlink 指向版本;workspace 套件 fedep 直接 symlink,開發時改 block 即時生效)
 - 測試頁 `web/src/pug/refactor-0809-module/index.pug`:registry 的 app block 指向 `/assets/lib/@plotdb/agent/main/`,api 仍為 `/api/agent`
 - 驗證:`/refactor-0809-module/index.html` 渲染與 chat tool loop(經模組 wsenv)均正常
 - `api/refactor-0809/` 與 `/refactor-0809/` 頁面暫留,確認 ok 後移除


## Streaming(三等級可開關)

用戶回饋「思考時不知道有沒有在做事」,加入即時回饋,等級 `none` < `tool` < `token`:

 - 後端 `opt.stream` 設允許上限(預設 token),`GET /provider` 回報;前端 `data.stream` 設期望等級(測試頁可用 `?stream=` 指定),生效等級取兩者較低者,前端要求超過允許時 console warning 後 fallback
 - `tool` / `token` 走 SSE(`data: {type: 'tool'|'delta'|'done'|'error'}`);tool 事件由 wsenv runTool 的 per-session hook 在執行當下推送
 - provider `send(text, cb)` 增加 `cb.onDelta`:anthropic 用 SDK 的 `messages.stream` + `finalMessage`;openai 用 `stream: true` 自行累積 content 與 tool_calls
 - chat 視覺層處理 `delta`(streaming 中的訊息即時累積,`reply` 時定稿;tool 事件後另起新訊息)
 - 驗證:curl 三種模式回應形式正確;瀏覽器實測 tool 事件在思考中即時出現、回覆逐字顯示、write 後自動重渲染


## 互動回饋與渲染錯誤自動修正

 - prompt 加一條:動工前先用一兩句話說明要做什麼再呼叫 tool,配合 token 串流,送出後很快就有文字出現
 - sandbox base 的 render 成功/失敗廣播 `rendered` / `render-error` 事件
 - chat base 收到 `render-error` 時自動把錯誤訊息回饋給 LLM 修正,safe guard 三道:只修 LLM 剛寫的 block(`lastWrote`)、同一輪最多 2 次(`data.maxFix` 可調)、成功渲染或用戶手動發話即歸零;`data.autoFix = false` 可整個關閉
 - 驗證:請 LLM 故意寫入 `notExistFn()` → 渲染失敗 → 顯示「渲染錯誤,嘗試自動修正 (1/2)」→ LLM read_file 移除該行 → 重新渲染成功
